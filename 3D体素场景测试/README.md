# 3D体素场景测试

## 同一道任务，不同 Agent + 大模型的交付结果

这里不是泛泛介绍“模型会不会做 3D”，而是把不同 Agent 与大模型组合在同一道具体任务下产出的作品并排呈现。每个 `test-*natural-selection-voxel` 目录保留一组独立结果；目录名标注模型版本，目录内的页面、源码、资源和记录共同构成这次交付。

## 任务是什么

制作一个可沉浸浏览的“自然选择号”体素宇宙飞船场景。核心要求是：

- 从飞船视觉设定中提取可辨识的主体结构，包括长轴舰体、中央居住环、舰脊与推进器。
- 以程序化体素构造主要舰体，让体素参与形体塑造，而不是只作装饰。
- 将飞船放进有纵深和氛围的宇宙环境，并通过镜头、灯光和推进效果表现空间感。
- 交付可运行的网页或单文件作品，并提供观察场景所需的镜头控制或操作说明。

同题的价值在于：场景目标相同，读者能直接看各组如何理解要求、形成视觉方案、实现体素结构并完成交付。它展示的是 **Agent + 模型组合的端到端结果**，而不是只看模型的一段文字回答。

## 为什么它适合观察 Agent + 模型能力

一个可浏览的体素场景要走完一段实际工作流：理解参考与文字约束、拆解舰体和环境、组织代码及资源、生成场景、安排观察视角，再运行检查并修复问题。这里既能看到模型产生的视觉与代码结果，也能检查 Agent 如何把工作从请求推进到可交付项目。

对比时可关注：

- **需求落实**：必需结构是否齐全，场景是否仍能被认作同一艘飞船。
- **空间建模**：舰体比例、环体与舰脊的连接、推进器数量和空间层次是否成立。
- **视觉表达**：主体构图、材质细节、光照、背景和推进效果是否彼此协调。
- **可操作性**：机位是否有助于观察结构，鼠标或触屏控制和界面说明是否清楚。
- **工程交付**：作品能否按说明启动，源码和资源是否齐备，是否有构建或验收证据。
- **Agent 推进质量**：是否有需求分析、过程记录、运行反馈和问题修复等可检查证据。

## 比较边界

当前仓库适合横向浏览作品和现有工程材料。各目录并未统一记录 Agent 产品/版本、完整提示词、工具权限、迭代轮数、硬件和同一套验收结果，因此不能仅凭最终页面断言某个模型或 Agent 单独更强，也不把目录里的自述数据当成跨作品统一评分。若要形成可复核排名，应先固定任务提示、Agent 配置、运行环境和评分表，再对每份交付用相同流程复测。

## 如何运行

各组交付形式和依赖不同：有的提供可双击打开的单文件，有的需要本地 HTTP 服务或开发服务器。运行前先看对应目录的 README、提示词文件或启动脚本；不要假定所有作品都能用同一种命令启动。
