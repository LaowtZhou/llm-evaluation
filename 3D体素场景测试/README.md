# 3D体素场景测试

本子项用于观察 Agent 与大模型协作完成 3D 体素场景任务时的端到端能力。仓库保存了多个模型围绕场景设计与生成形成的测试项目，既有“自然选择号”主题，也包含火山精灵龙场景。

## 为什么这个测试能体现 Agent + 模型能力

生成一个可运行、可浏览的 3D 场景，不只是让模型写出一段代码。任务通常要经过“理解目标—规划结构—生成实现—接入资源与工具—运行检查—发现问题并修正”的完整链路：

- **模型能力**：理解自然语言约束；构思空间布局与视觉层次；编写或修改场景代码；保持物体、材质、灯光和主题之间的一致性；根据运行结果迭代细节。
- **Agent 能力**：把目标拆成步骤；选择和调用合适的文件、脚本与开发工具；组织资源和代码；执行构建或检查；读取错误与反馈并推动修复；把中间过程收敛成可交付的项目。
- **协作效果**：最终体验取决于模型生成质量，也取决于 Agent 能否正确安排步骤、传递上下文、使用工具和验证结果。只看模型回答文本，无法完整呈现这种协同能力。

因此，这类测试可以把抽象的“会不会做”转化为可检查的产物和过程证据：场景是否符合要求、能否启动、结构是否完整、视觉重点是否清晰、遇到问题能否修正，以及最终交付是否便于他人复现。

## 建议的共同评估维度

为使不同模型之间的比较更公平，建议在相同提示词、Agent 工具权限、资源和运行环境下记录：

1. **任务遵循**：是否满足指定主题、对象、布局、交互和限制条件。
2. **空间与视觉表达**：场景层次、比例、构图、配色、材质和细节是否清楚。
3. **工程可运行性**：项目结构、依赖、启动说明和运行稳定性是否足以让他人复现。
4. **工具使用与修复**：Agent 是否选对工具、正确读取反馈，并有效处理构建或运行问题。
5. **迭代效率**：从初稿到可交付版本所需的步骤、返工量和人工介入程度。
6. **交付质量**：源码、资源、说明和最终场景是否完整、一致、便于检查。

建议同时保存提示词、模型及版本、Agent 配置、执行过程摘要、运行环境和评分依据。现有样例的条件并不保证完全一致，因此它们适合展示测试方法与案例；在统一协议和量表下复评之前，不应据此直接得出模型排名或普遍能力结论。
